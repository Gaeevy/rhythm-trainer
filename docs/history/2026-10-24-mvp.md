# 2026-10-24 — MVP history

Historical summary of the work begun on 2026-10-24. Current behavior and working
instructions are in the [practice guide](../practice.md), [lesson format](../lessons.md),
[development guide](../development.md) and [AGENTS.md](../../AGENTS.md).
Full implementation detail and the original plans remain in Git history.

## Goal and decisions

Build a simple looping drum trainer for jazz practice on a Millenium MPS-850,
with custom lessons generated outside the app and committed as JSON.

- Extend the existing GitHub Pages project; keep browser timing/input local.
  Flask, Railway, accounts and a database were unnecessary for the MVP.
- Use integer musical ticks for lessons and precise timestamps for assessment.
- Build lanes dynamically from lesson tracks; retain keyboard input for testing.
- Expand from four instruments to twelve, with explicit closed/open/pedal hi-hat.
- Replace MIDI Learn and browser mapping overrides with the observed repository
  MPS-850 config and automatic connection. Both ride zones count as Ride.
- Discover lessons from files instead of maintaining a registry or browser editor.
- Use recorded guide drums and preserve the metronome. Synthesized drum fallback
  was later removed by explicit user choice; recording errors now require retry.

## Delivery

| Milestone | Outcome |
| --- | --- |
| 1. Model and setup | JSON validation, integer ticks and local tooling |
| 2. Playback and lanes | Native-clock loops, dynamic lanes, count-in and mixer |
| 3. Keyboard and assessment | Precise early/on-time/late/missed/extra matching |
| 4. MIDI | Automatic MPS-850 input, observed pad mappings and retry/reconnect |
| 5. Controls and lessons | Saved preferences, key remapping, file-based catalog |
| 6. Browser/release checks | Isolated Chrome, root/subpath artifact verification |
| 7. Physical acceptance | Full real-kit timing/audio/reconnect check remains separate |

The MVP and nine practice lessons were deployed through Pages on 2026-10-25.
The later notation work is summarized in [notation history](2026-11-04-notation-plan.md).
Physical note observations and simulated MIDI checks do not establish end-to-end
latency acceptance.

## Deferred scope

Accounts, activity storage/progress, AI/MCP lesson authoring, a browser editor,
additional meters, dynamics and separate cymbal articulations remain future work.
No backend is needed until an accepted requirement requires one.
